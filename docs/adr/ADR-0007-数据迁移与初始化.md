# ADR-0007 · ORM、迁移与数据初始化

- **状态**：`accepted`（按上轮推荐默认值推进，可随时 supersede）
- **日期**：2026-11-14
- **相关**：[`ADR-0005`](ADR-0005-端口与适配器.md)、[`ADR-0006`](ADR-0006-桌面端双模式.md)

## 背景

旧项目用 TypeORM 0.3，线上曾明确禁止 `synchronize: true` 触发表结构 ALTER（会破坏生产数据）。新项目需要一套**可重放、可演示、不碰真实数据**的迁移与初始化方案。

## 决策

| 项 | 决策 |
|---|---|
| ORM | **Prisma**（类型生成与 migration 体验更契合契约优先，展示价值更高） |
| 迁移 | 只走 `prisma migrate`，**任何环境禁用 `db push` / `synchronize`**；迁移文件纳入版本库 |
| 种子 | `prisma/seed.ts` 生成三个演示账号（管理员 / 销售 / 只读）+ 商品、库存、订单样例 |
| 演示库 | SQLite 用于桌面 `demo` 模式；迁移差异限制在 Infrastructure |
| 备份 | 本地演示数据可随时重建，严禁接入任何线上库连接串 |

### 从旧项目迁移的经验（只迁经验）

- 金额只由服务端计算 → `Money` 值对象 + 服务端定价
- 下单即占库存 → `reservedQty` 状态机，事务边界在 Application
- 状态终态不可回退 → 显式状态机文档
- 订单不做物理删除 → 状态标记 + 软删除

## 备选方案

| 方案 | 否决理由 |
|---|---|
| 保留 TypeORM 0.3 | 经验可复用，但类型安全与迁移体验弱于 Prisma，且会把旧项目的实体平铺习惯带进新仓库 |
| 裸 SQL + 手写迁移 | 可控但工作量大，与契约优先的类型链路脱节 |
| `synchronize` / `db push` 自动同步 | 🔴 明确禁止，旧项目红线 |

## 后果

**正面**：迁移可重放、演示数据一键生成、类型与 schema 同源。
**负面**：Prisma 对 SQLite/Postgres 差异需额外注意（如枚举、JSON 字段），团队需学习成本。

## 验收

- [ ] 空库执行 `migrate deploy` + `seed` 后可直接跑演示脚本
- [ ] 仓库中无 `synchronize: true` / `db push` 脚本
- [ ] 演示数据与任何真实业务数据零关联
