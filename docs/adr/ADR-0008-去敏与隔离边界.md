# ADR-0008 · 去敏与隔离边界

- **状态**：`accepted`
- **日期**：2026-11-14
- **相关**：[`ADR-0001`](ADR-0001-新项目文档体系重建.md)、[`ADR-0002`](ADR-0002-admin-前端起点选型.md)、[`../domain/glossary.md`](../domain/glossary.md)

## 背景

本项目要公开给面试官和客户看，且必须能在客户机器上一键运行。旧项目含有真实商户号、APIv3 密钥、域名、用户数据、支付通道与线上部署绑定；旧启动器还带游戏逆向、封包、Flash 相关能力。任何一项泄漏或出现在代码里，都会同时造成**安全事故**与**展示事故**。

## 决策

| 边界 | 规则 |
|---|---|
| 旧仓库 | 与 `D:\Project\xy_project` **完全隔离**：不复制、不引用、不修改；xy-admin 完全不参与 |
| 凭据 | 一律 `.env`；仓库只提交 `.env.example`，值全部为开发默认值 |
| 线上资产 | 不出现 Render / Neon / Vercel / 真实域名 / 商户号 / 私钥 |
| 业务禁词 | `docs/domain/glossary.md` 禁用词表，CI 扫描命中即失败 |
| 演示数据 | 全部虚构；`seed` 可随时重建，禁止导入任何真实数据 |
| 依赖 | 演示默认走 Mock 适配器（ADR-0005），不触达任何外部真实服务 |
| 上游合规 | 保留 `apps/erp-admin/LICENSE`（MIT），来源与快照记入 `THIRD-PARTY-NOTICES.md` |

### 明确不迁移的资产

游戏 / 卡密业务规则、启动器源码、封包与 SWF 逆向、真实用户数据、线上数据库、支付凭据、部署拓扑。

### 明确迁移的资产

领域经验（金额服务端算、库存占用、状态终态、审计脱敏、禁 synchronize）与工程教训（husky 自动 stash 删库事故），以抽象原则形式落地。

## 备选方案

| 方案 | 否决理由 |
|---|---|
| 从旧项目复制后手动删敏感信息 | 删不干净，且违反隔离红线（用户 2026-11-14 已纠正） |
| 用真实数据的脱敏副本 | 仍有合规风险，演示完全不需要 |
| 演示时连线上测试环境 | 依赖外网与线上账号，现场不可控 |

## 后果

**正面**：仓库可公开、现场可离线、安全与叙事风险同时消除。
**负面**：演示数据与真实业务形态有差异，需要在讲解时说明「这是刻意构造的通用 ERP 样例」。

## 验收

- [x] 新仓库无 xy_project 复制痕迹、无禁用词命中
- [x] `.env.example` 不含任何真实凭据
- [ ] CI 加入密钥与禁用词扫描（P1）
- [ ] 断网状态下 `pnpm dev` + 桌面 `demo` 模式可完整演示
