# ADR-0006 · 桌面端双模式（Demo / Live）

- **状态**：`accepted`（按上轮推荐默认值推进，可随时 supersede）
- **日期**：2026-11-14
- **相关**：[`ADR-0002`](ADR-0002-admin-前端起点选型.md)、[`../../架构总纲.md`](../../架构总纲.md) 第 6 节

## 背景

桌面端既要作为**求职/客户现场的作品集壳**（可能没网、没 Docker、没后端），又要能演示**真实 ERP 业务流程**。单一数据源无法同时满足。

## 决策

| 模式 | 数据源 | 触发条件 | 用途 |
|---|---|---|---|
| `demo` | 本地 SQLite（只读演示库 + seed） | `DESKTOP_MODE=demo`（默认） | 离线展示，可跑真实 CRUD 与查询，无需后端 |
| `live` | 本地 `erp-api` HTTP | `DESKTOP_MODE=live` | 连真实服务，演示数据落库与多端一致 |

- 切换由 **preload 层统一数据网关**决定，renderer 只依赖接口、不感知来源
- 进程模型：main（窗口/生命周期/自动更新）、preload（`contextBridge` 白名单 API）、renderer（无 Node 权限）
- 安全基线：`contextIsolation` + `sandbox` 开启、`nodeIntegration` 关闭、CSP、IPC 入参用 Zod 校验

### 起点评估

同作者的 `un-pany/v3-electron-vite` 与 admin 同构，是 `apps/desktop` 的候选起点；**与旧仙域启动器无关**。是否采用另开 ADR，本决策不绑定具体模板。

## 备选方案

| 方案 | 否决理由 |
|---|---|
| 纯静态 JSON 演示数据 | 只能翻页，跑不了查询/写入，说服力弱 |
| 只连本地 API | 现场必须起 Docker + 后端，演示风险高 |
| 打包内嵌 PostgreSQL | 体积与启动成本过高 |

## 后果

**正面**：任何环境都能演示；SQLite 与 Postgres 走同一套端口接口，可验证「适配器可替换」。
**负面**：需维护两份数据初始化逻辑；SQLite 与 Postgres 的 SQL 差异要限制在 Infrastructure 层。

## 验收

- [ ] 断网 + 未启动 Docker 时，`demo` 模式可完整跑通演示脚本
- [ ] `live` 模式数据与 `erp-admin` 一致
- [ ] renderer 中无 `ipcRenderer` / Node API 直接使用
