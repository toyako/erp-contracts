# ADR-0005 · 端口与适配器（外部依赖可替换）

- **状态**：`accepted`
- **日期**：2026-11-14
- **相关**：[`../../架构总纲.md`](../../架构总纲.md) 第 3、4 节

## 背景

现场演示不能依赖任何真实支付通道、云存储或线上账号；客户二次定制时会替换数据库、通知渠道或支付服务商。若领域层直接调用 SDK，这两件事都做不到。

## 决策

外部能力一律定义为 **Domain/Application 层的端口接口**，实现放在 Infrastructure：

| 端口 | 生产适配器 | 演示适配器 |
|---|---|---|
| `PaymentGateway` | 真实网关适配器（客户自备凭据） | `MockPaymentGateway`（本地即时成功/可注入失败） |
| `ObjectStorage` | S3 兼容实现 | `LocalFileStorage` |
| `Cache` | Redis | `InMemoryCache` |
| `Notifier` | 邮件/短信/IM | `ConsoleNotifier` |
| `Database` | PostgreSQL（Prisma） | SQLite（桌面 Demo 模式，见 ADR-0006） |

- 适配器通过依赖注入注册，切换由环境变量决定，**领域代码零改动**
- 领域层禁止出现 `axios` / `pg` / `prisma` / 任何 SDK import

## 备选方案

| 方案 | 否决理由 |
|---|---|
| 直接在 service 里调 SDK | 演示依赖真实账号，客户替换需改业务代码 |
| 大而全的 provider 抽象层 | 过度设计；端口按实际外部能力逐个定义即可 |

## 后果

**正面**：`DESKTOP_MODE=demo` 下全链路可离线跑；客户换支付/存储只写新适配器；单测可用内存实现。
**负面**：多一层接口与 DI 配置；需防止有人图省事绕过端口（靠 CI 静态检查兜底）。

## 验收

- [ ] 领域层 import 扫描无 SDK 命中
- [ ] Mock 适配器下可跑通「登录 → 下单 → 占库存 → 收款 → 履约」
- [ ] 切换适配器不需修改任何 domain/application 文件
